# 趋势页

Status: ready-for-agent
Type: enhancement

## 问题陈述

用户需要跨日期查看摄入热量、记录习惯和每日平均营养，现有页面仅展示单日饮食清单。

## 解决方案

新增「趋势」标签，沿用插件面板的样式。展示热量走势图、当前连续记录天数、最长连续记录天数，以及蛋白质、脂肪、碳水的每日平均摄入量。宽面板利用横向空间，窄面板上下排列。

## 用户故事

1. 作为用户，我希望从顶部进入趋势页，方便查看长期记录。
2. 作为用户，我希望默认查看最近 7 天，了解近期摄入。
3. 作为用户，我希望切换 30 天、90 天和全部，比较不同时间范围。
4. 作为用户，我希望日期范围截至今天，便于理解统计时间。
5. 作为用户，我希望全部范围从最早饮食记录开始，便于回顾历史。
6. 作为用户，我希望看到每天摄入热量，了解变化。
7. 作为用户，我希望同时看到每天估算维持热量，便于对照。
8. 作为用户，我希望历史维持热量按当日生效资料估算，保留当时参考。
9. 作为用户，我希望没记餐的日期在摄入曲线上留空，理解记录缺口。
10. 作为用户，我希望点击图中的日期进入对应饮食记录，查看当天食物。
11. 作为用户，我希望看到当前连续记录天数，了解记录习惯。
12. 作为用户，我希望今天未记录时仍显示截至昨天的连续天数，便于当天继续记录。
13. 作为用户，我希望看到全部历史的最长连续记录天数，了解历史情况。
14. 作为用户，我希望切换范围时两项连续天数保持全历史口径，方便比较。
15. 作为用户，我希望分别看到蛋白质、脂肪、碳水的每日平均克数，了解营养摄入。
16. 作为用户，我希望平均值只计入有记录且该项资料完整的日期，避免漏填造成误导。
17. 作为用户，我希望各项营养分别判断完整性，充分利用已有资料。
18. 作为用户，我希望填写的 0 参与平均，准确反映已知数值。
19. 作为用户，我希望看到各项平均参与计算的天数，理解统计依据。
20. 作为用户，我希望无完整资料时显示「资料不足」，了解数据状态。
21. 作为用户，我希望在不同宽度及主题的面板里都能查看和操作趋势页。

## 实现决定

- 复用现有页面请求、SQLite 仓储、份量换算和维持热量估算。提供一个只读趋势查询，返回日序列、全历史连续天数及各项营养日均和有效天数。
- 以设备所在时区确定今天。7 天包含今天及之前 6 天，30 天、90 天同理。全部范围从截至今天的最早记录开始。
- 每日摄入从当前食物库按需计算，遵循 ADR 0001。维持热量按日期生效的个人资料版本计算，遵循 ADR 0003。
- 没有记录的日期摄入为空。没有可用个人资料的日期维持热量为空。
- 一天至少有一条饮食记录即为记录日。连续天数按全部历史截至今天计算。当前连续从今天或昨天开始往前数。
- 每项营养仅在当天所有记录引用的食物都填了该项时累计日总量。以这些完整记录日的总量除以完整天数。未知值保留缺失语义，显式 0 参与计算。
- 趋势页面、图表和统计卡按职责拆分。查询和统计在业务模块完成。图表可选择日期并打开对应饮食清单。

## 测试决定

- 通过页面实际使用的请求接口与真实 SQLite 测试库验证可观察结果，沿用已有宿主接口及单日摘要测试做法。
- 覆盖日期范围、缺记录留空、历史个人资料、记录增删改、全历史连续天数、逐项营养完整性、显式 0 和资料不足。
- 用户自行查看页面布局、视觉和日期跳转。仅覆盖日常实际使用场景。

## 范围之外

营养目标设置、体重走势、新增 Agent 工具和发布新版本。

## 补充说明

蛋白质示例中，某天一条记录缺资料则整天排除该项平均，其余完整日合计 40 克时显示 40 克及 1 天数据完整。其他营养分别判断。
