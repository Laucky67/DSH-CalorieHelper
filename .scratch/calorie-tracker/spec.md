# DSH 插件「卡路里记录」

Status: ready-for-agent
Type: enhancement

## 问题陈述

用户希望在 DSH 里管理常吃的食物、记录每天各餐吃了什么，并查看已记录摄入与估算维持热量的差值。用户既可以操作页面，也可以让 DSH 中的 Agent 查询或修改食物库和饮食记录。补记历史饮食时，需要使用那个日期生效的个人资料来估算维持热量。

## 解决方案

在 DSH 侧边栏加入「卡路里记录」，点击后在主界面打开今天的饮食清单。页面可切换日期，有独立的食物库和个人资料入口。Agent Tools 提供食物库和饮食记录的增删查改，并能一次写入同一天、同一餐的多条饮食记录。

## 用户故事

1. 作为 DSH 用户，我希望从侧边栏打开「卡路里记录」，方便直接在主界面记餐。
2. 作为记餐用户，我希望默认看到今天的饮食清单，方便继续记录当天的饮食。
3. 作为记餐用户，我希望切换日期，方便补记或查看过去的饮食。
4. 作为记餐用户，我希望清单按早餐、午餐、晚餐、零嘴分组，方便判断每条记录属于哪一餐。
5. 作为记餐用户，我希望从每餐的添加入口选食物并填写食用量，方便一次录入一条饮食记录。
6. 作为记餐用户，我希望录入时直接新增食物，方便记下食物库里还没有的食物。
7. 作为记餐用户，我希望点击食物旁的铅笔进入食物编辑页，方便给已有食物补份量换算。
8. 作为记餐用户，我希望能修改记录的食用量和日期或餐别，也能删除误记的记录，方便纠正清单。
9. 作为记餐用户，我希望在食用量无法计算热量时收到明确提示，方便填入可用的量或补齐换算后保存。
10. 作为食物库使用者，我希望新增、查看、编辑和删除食物条目，方便维护经常使用的食物。
11. 作为食物库使用者，我希望可以给食物填写热量和可选的蛋白质、脂肪、碳水、钙，方便保留手头已有的营养资料。
12. 作为食物库使用者，我希望能直接定义每个鸡腿堡、每片面包或每 100 克米饭的热量，方便按日常用法记录食物。
13. 作为食物库使用者，我希望可以为米饭添加「1 碗 = 150 克」这样的份量换算，方便按碗或按克记。
14. 作为食物库使用者，我希望同名食物条目不能重复保存，方便辨认和选用食物。
15. 作为食物库使用者，我希望已被饮食记录引用的食物受到删除保护，方便之后打开清单时仍能看到并计算这些记录。
16. 作为记餐用户，我希望修正食物库资料后再查看清单时能看到按当前资料计算出的热量，方便对照最新的资料。
17. 作为记餐用户，我希望可以设置出生日期、性别、身高、体重和日常活动等级，方便估算维持热量。
18. 作为记餐用户，我希望资料还没填齐时也能记餐和看摄入热量，方便之后再补资料。
19. 作为记餐用户，我希望首页热量摘要显示摄入热量、估算维持热量和差值，方便知道当天记下的摄入量距离维持热量还有多少。
20. 作为记餐用户，我希望差值在低于估算值时直接显示数字、超出时带减号、相等时显示 0，方便迅速读懂结果。
21. 作为记餐用户，我希望今天多次修改个人资料时使用当天最新的一版，方便看到当天更新后的估算值。
22. 作为记餐用户，我希望查看昨天时仍用昨天生效的资料版本，方便比较历史日期对应的摄入和维持热量。
23. 作为使用 Agent 的用户，我希望搜「山姆的胡萝卜」也能找到「山姆胡萝卜」，方便用自然说法找到食物条目。
24. 作为使用 Agent 的用户，我希望它可以一次新增一整餐的多条记录，并在同次调用里添加缺少的新食物，方便少说一遍餐别和日期。
25. 作为使用 Agent 的用户，我希望批量记餐有一项出错时整批都暂不写入，并能指出哪一项出错，方便修正后整批重试。
26. 作为使用 Agent 的用户，我希望它可以按日期和餐别查询饮食记录，也可以单独修改或删除指定记录，方便核对和更正。
27. 作为使用 Agent 的用户，我希望查询饮食记录时拿到按实际食用量算出的已知营养值和查询范围的总热量，方便提出营养相关的问题。

## 实现决策

- 界面按 DSH 的侧边栏和主界面方式接入。打开时选中今天。顶部可切换日期，热量摘要只显示摄入热量、估算维持热量和差值。清单按餐别排列，食物库和个人资料各有入口。布局、字体层级和控件应清晰统一，便于快速记餐。所有用户可见文案遵守项目的前端文案要求。
- 食物条目持久化 ID、唯一名称、营养资料及可选的份量换算。营养资料共用一个计量基准，包含数量和单位，热量用千卡且必填。蛋白质、脂肪、碳水可以用克，钙可以用毫克。缺失项省略，已知为零的项保存为 0。基准可按克、毫升、个、片、份等单位定义。
- 食用量含数量和单位。计算时可使用相同单位、可直接换算的标准单位，或该食物定义的自定义份量。食用量能算出热量才可以保存饮食记录。用户为已有食物补换算时，通过铅笔进入食物编辑页。Agent 先保存已有食物的换算，再提交饮食记录。
- 饮食记录持久化日期、餐别、食物条目引用和食用量，并有可更新和删除的记录 ID。按 ADR 0001，在查询时读取食物库里的当前名称、营养值和份量换算，按食用量得出摄入热量和可得的营养值。食物条目有引用时禁止删除。
- 个人资料包括出生日期、性别、身高、体重和四档日常活动等级，从主要是日常活动到非常活跃。按 ADR 0003，每次保存个人资料修改都新增版本。查看某日时取当日或更早最后保存的版本，包括同一天多次修改时的最后一版。
- 以所查看日期计算周岁，使用生效版本的性别、身高、体重和活动等级，按 NASEM 2023 表 5-16 的 19 岁及以上成人公式估算维持热量。所选日期没有生效资料版本、资料不足或年龄不适用时，维持热量和差值显示 `—`。差值等于该日估算维持热量减去已记录摄入。正数显示如 `375 千卡`，负数显示如 `−225 千卡`，相等时显示 `0 千卡`。
- 食物库工具为 `food_search`、`food_create`、`food_update`、`food_delete`。搜索可按食物 ID 精确查询，也可按名称返回相关候选，完全匹配优先，允许忽略空白、标点或「的」等差异。候选包含 ID、名称、营养资料和份量换算，由 Agent 选择。写入涉及已有食物时使用食物 ID。
- 饮食记录工具为 `diet_create`、`diet_query`、`diet_update`、`diet_delete`。新增请求提供批次共用的日期和餐别，以及至少一条食用量和食物引用或新食物资料。按 ADR 0002，整批校验通过后，饮食记录和随批新增的食物一起保存。失败时指出出错项和原因，整批暂不写入。
- `diet_query` 按日期和可选餐别查询，也可按记录 ID 查询。每条结果包含记录 ID、食物名称、食用量、摄入热量和按食用量算出的已知营养值，并提供查询范围内的总热量。`diet_update` 按记录 ID 修改指定字段，包括食用量、日期或餐别。`diet_delete` 按记录 ID 删除。Agent 自主调研和调用工具，工具负责校验、执行和返回结果。

## 测试决策

- 实施 Agent 负责自动化测试，优先通过实际 Agent Tools 调用验证食物和饮食记录的公开行为。对工具无法覆盖的个人资料版本和每日摘要，通过界面所用的公开业务入口做集成验证。以输入与可见结果为断言依据。当前仓库尚无插件实现和可复用的测试。
- 食物库场景覆盖增删查改、重名拒绝、被引用时拒绝删除、搜索「山姆的胡萝卜」能返回「山姆胡萝卜」，以及同一查询返回多个候选时可用 ID 指定目标。
- 记餐场景覆盖按整份及半份计算、克与千克的换算、自定义「碗」的换算、无法换算时拒绝保存、修正食物资料后旧记录查询采用当前资料、可选营养值按食用量缩放并区分缺失与零。
- 批量场景覆盖同一日期和餐别提交多条、随批新增食物成功，以及任一项无效时饮食记录和随批新增的食物均未写入。通过重新查询确认结果。
- 摘要场景覆盖 NASEM 公开算例、日期切换、同一天多次修改取最新版本、之前日期保留原版本、无生效资料时的可用状态与差值正负零。
- 用户自行查看页面。查看场景包括从侧边栏打开今天、切换日期、各餐逐条记餐、铅笔按钮进入食物编辑页、食物库和个人资料入口，以及首页布局和文案是否符合预期。
